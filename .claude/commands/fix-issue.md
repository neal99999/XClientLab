先读取仓库根目录的 `.claude/neal/project-context.md`（用 `git rev-parse --show-toplevel` 定位，不要写成相对当前目录的路径）并遵守共用规则。

# 输入
`$ARGUMENTS` 是问题描述、issue 编号/链接或错误日志。为空时只问一句「要修哪个问题？给我描述、issue 号或报错日志」然后停止。

# 流程
1. **定位**：根据关键词/堆栈找到相关文件与调用链；用 `grep`/`glob` 收敛范围，先读代码再下结论。
2. **复现/确认**：能命令行复现的（编译错误、SwiftPM 测试、脚本）先复现；不能复现的说明原因与证据，不要假装复现过。
3. **根因**：写清触发条件、调用路径、为什么现在才出问题；区分「已确认」与「推测」。
4. **修复**：最小 diff，只改与问题相关的代码；不顺手重构、不清理无关告警、不改 `Pods/`。
5. **验证**：按 `.claude/rules/testing.md` 做编译/测试/手动回归；无法验证的明确标注。
6. **交付**：中文总结——根因、改了哪些文件（路径:行号）、验证结果、未验证项与手动回归建议。

# 约束
- 下单/撤单等非幂等接口不要加重试。
- 金额计算只用 String 大数扩展，不引入 `Double`。
- 涉及共享单例/通知/WebSocket 订阅的改动，主动列出回归范围。
- 不提交、不推送；用户明确要求时才执行 git 写操作。
